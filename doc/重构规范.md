# 重构规范（三打一项目）

> 本文档是本仓库**重构类任务的执行规则**，2026-11-16 全项目重构中确立。
> 触发重构任务时必须先读本文；日常小改动遵循 AGENTS.md 即可。
> 配套：[AGENTS.md](../AGENTS.md)（总体规范，第 4 章架构 / 第 7 章测试）；最佳实践清单见其「Godot 最佳实践」章节。

## 1. 适用范围与总原则

适用于：死代码清理、兜底代码根治、模块/文件/函数拆分与合并、命名与契约统一等**不改变外部行为**（或明确以行为修正为目的的兜底根治）的结构性改动。

总原则：

1. **先有安全网再动刀**：动手前基线必须全绿（`--import` → `run_tests.gd` → 涉 UI 加 `smoke_ui.gd`）；基线不绿先修基线。
2. **小步提交**：一个主题一个提交（`类型: 中文摘要`），每步验证后提交；禁止「大爆炸」式一次性巨改，出问题可二分定位。
3. **行为不变者测试不变**：纯结构性重构不修改断言；若必须改测试触点（如成员迁移），只改引用路径不改断言语义。
4. **根治优于掩盖**：发现兜底代码，定位根因后从根因修复（见第 3 章）；禁止新增兜底去掩盖旧兜底。

## 2. 死代码识别与清除流程

1. **识别**：候选符号（方法/成员/常量/节点）逐一 `grep -rn "符号名" --include="*.gd" core script test` 交叉验证；测试专用 API 需区分「守护规则编码」（如 `Card.deck_points`，保留）与「死 API 的死测试」（如曾只被测试调用的 `CardWidget.set_face_up`，连测试一起改写）。
2. **清除**：
   - 全仓库零引用 → 删除；
   - 仅内部使用却公开 → 转私有（`_` 前缀）；
   - 「可配置」从未被定制 → 收敛为常量（参照 `DashedRoundedFrame`）；
   - 误导性注释（声称的用途与事实不符）→ 随代码一并修正。
3. **验证**：删除后 `--import` + 全量测试；公开 API 删除需 grep UI/测试调用点同步更新。

## 3. 兜底代码：分类、根治协议与白名单

### 3.1 识别特征（出现即怀疑）

| 类别 | 典型形态 | 本仓库实例（已根治） |
|---|---|---|
| 信号兜底 | 定时轮询「校验显示与数据一致，防御任何信号遗漏」 | `_process` 0.5s 全量刷新轮询 |
| 竞态补丁 | 注释写「不得清理，否则把新按钮一并删掉」 | submit 内的破坏性清理规避 |
| 吞错 | 失败分支静默继续、返回默认值掩盖异常、哨兵值（seat=-1）流入后续逻辑 | `_settle_trick` 失败静默死锁 |
| 镜像逻辑 | 同一规则在「校验方」与「生成方」两份手写实现 | `_count_identity_pairs` ≡ `_identity_pair_count` |
| 双义复用 | 一个字段先后表示两种含义 | `bottom`（翻底前/扣底后） |
| 布局兜底 | 「首帧未就绪时的兜底宽度/默认值」 | `avail < 100 → 1100` |
| 防御性重复校验 | 调用方已校验、被调方再校验同一不变式（见 3.3 白名单边界） | |

### 3.2 根治协议（五步）

1. **定位根因**：问「这个兜底在防什么？」追溯到第一个出错的假设（如轮询防的是信号遗漏 → 根因是刷新被三重触发且无单一入口；「不得清理」防的是同步信号重入 → 根因是按钮生命周期无唯一所有者）。
2. **从根因修复**：重建正确结构（单一刷新入口 / ActionBar 独占生命周期 / 显性 fault 信号 / 合并公共口径 / 拆分双义字段 / 挂起渲染待布局就绪）。
3. **用例守护**：为根因路径补正反用例（如 `test_settle_failure_is_loud`、`test_trick_settle_display_pauses`）；UI 行为回归必须落在 test_ui.gd。
4. **删除兜底**：根因修复被测试守护后，兜底代码整体删除——不允许「留着以防万一」。
5. **信号时序不变式**：任何信号发出前状态必须完全就绪（`_begin_game` 先 `auction.begin` 再 `_set_phase` 的教训：phase_changed 同步到达 UI 时读到了未初始化的 bids）。

### 3.3 白名单：以下形态**不是**兜底，允许保留并注释说明

- **引擎行为适配**：`HandArea._input()` 全局命中测试——Godot 按住鼠标期间把 motion 路由给按下时的控件（mouse_focus 捕获），相邻牌收不到 gui_input，属引擎特性适配。
- **演示节奏等待**：`await _trick_timer.timeout`（结算停留 1.5s 的展示节奏）、AI 行动 0.7s 节拍——表现层节奏，非竞态规避。
- **生命周期守卫**：场景切换后 `is_inside_tree()` 早退（toast/动画回调防悬空）。
- **引擎不信任调用方**（AGENTS.md 第 4 章架构原则）：`submit_*` 自行校验输入、`Auction.submit` 校验轮次——这是防御外部输入的架构约定，不是内部逻辑的重复校验；边界 = 校验「调用方输入」，不校验「自己刚写入的状态」。
- **查表魔数带出处**：`BID_CALIB` 等离线校准数据须注明来源脚本与重跑条件（已注明）。

## 4. 模块拆分原则

1. **单一职责**：一个文件一个变化理由（`auction.gd` 只管拍卖规则，`scoring.gd` 只管分级收益）。
2. **门面保公共面**：拆分后原入口保留为薄门面转发（`AiPolicy` → `AiBidding/AiPlay`；`GameEngine.BID_PASS` → `Auction.BID_PASS`），调用点与测试零 churn；门面只做「解包 + 转发」，不得长出逻辑。
3. **core 纯逻辑不变式**：拆出的 core 模块仍 `extends RefCounted`、零 Node/场景/时序/IO 依赖——由 `test_architecture.gd` 机器守护，新增 core 文件自动纳入扫描。
4. **数据进/决策出**：策略与领域模块的函数签名只收数据参数（hand/trump/plays…），不收引擎对象、不读内部字段；随机源等依赖由调用方注入。这是 C/S 复用（M4）与单测友好的共同前提。
5. **状态归一所有**：一块状态只有一个所有者（bids/turn 归 Auction，选中态归 HandArea，按钮归 ActionBar）；派生状态用访问器（`get_last_trick()` 由 trick_history 派生），不存镜像。
6. **UI 控制器 ≤600 行**：超过即按职责拆组件（参照 game_table 1002 → 538 + 五组件）；测试触点（`_submit_human_*`、`_ai_timer`）留在控制器作门面。
7. **常量单一事实源**：跨组件共用常量放唯一处（`UiStyle.MAIN_TABLE_CENTER`），禁止两份「应该相等」的数字。

## 5. 验证顺序（每次改动后）

```
1) --import                 无脚本/资源错误
2) run_tests.gd             全绿（当前 12 套件 82+ 用例，含架构守护）
3) smoke_ui.gd              涉 UI/引擎流程时
4) Web 导出 + 浏览器验收     涉视觉/布局时（见第 6 章）
```

## 6. HTML 导出与浏览器验收工作流（固定流程）

UI/布局/字体改动后，必须走完整视觉验收闭环（headless 测试不覆盖「看起来对不对」）：

```bash
# 0) 前置：文案有新增字符时先重跑字体子集（否则浏览器中显示豆腐块）
python -I tool/subset_font.py

# 1) 导出 Web 版（gl_compatibility；导出过滤已排除 test/ doc/ tool/）
S:/Program/Godot/Godot_v4.7.2-stable_win64_console.exe --headless --path . --export-release "Web"

# 2) 本地静态服务
cd build/web && python -m http.server 8765

# 3) 内置浏览器打开 http://127.0.0.1:8765 截图验收
#    （browser-use 技能）：主菜单 → 开始 → 叫分 → 叫主 → 扣底 → 出牌 → 结算面板
#    检查：布局/居中/半字号留空/字体渲染无豆腐块/按钮可用

# 4) 发现问题 → 改代码 → 回到第 1 步（此循环即「导出-验收-修正」工作流）
```

要点：

- **字体**：浏览器无系统字体回退，中文必须打包（`font/NotoSansSC-Regular.subset.otf`，子集自 Noto Sans SC OFL；字集=源码字符+ASCII+全角标点缓冲）。主题 `theme/default.tres` 设为项目默认字体，桌面/Web 统一。
- **Web 特性守卫**：`OS.has_feature("web")` 分支隐藏退出按钮（quit() 无效）与自检按钮（test/ 未打包）；自检用运行时 `load()` 而非静态 preload，避免把 test/ 拖进导出包。
- **导出模板**：一次性安装到 `%APPDATA%\Godot\export_templates\4.7.2.stable\`（tpz 解压出 templates/ 内件）；GitHub 直连慢时用 `gh release download`。
- 验收通过后关闭本地服务；`build/` 不入库。

## 7. C/S 联机预留约定（M4 实施前的持续约束）

本次重构为联机预留的口子，**后续任何改动不得破坏**（由 `test_architecture.gd` 守护）：

1. **core 服务端可复用**：零 Node/场景/时序/IO 依赖，可在服务端确定性重放（无墙钟、无随机全局态；随机源集中可注入）。
2. **submit_\* 唯一状态变更入口**：值匹配契约（`Card.key()` 唯一）= 网络消息可直接映射为 `submit_bid/trump/discard/play` 调用，无须传对象引用。
3. **信号唯一 UI 复制通道**：客户端 UI 只凭信号 + 查询接口呈现；禁止 UI 直写引擎状态（`test_engine_public_api_is_submit_only` 白名单守护公开面）。
4. **AI 数据进/决策出**：`AiBidding/AiPlay` 不持有引擎引用——服务端可按玩家独立调用，客户端本地预测也可复用。
5. **门面是适配层**：`AiPolicy.choose_play(engine, seat)` 只做引擎状态解包；联机落地时服务端绕过门面直调纯模块。

> **落地注记（2026-11-18，M4 已实施）**：以上口子在 M4 中按原样兑现——服务端（`server/`）权威运行 GameEngine 并直调纯模块（第 1/4/5 条）；`Card.key()` 值匹配即网络消息契约（第 2 条）；客户端不跑引擎，`net/table_view.gd` 以可见性裁剪的视图状态提供与引擎同构的信号+查询面（第 3 条），game_table 经鸭子类型零语义改动复用。后续联机演进（M5 部署、观战、复盘）不得破坏本约束；实施细节与踩坑记录见《三打哈-Godot工程计划.md》§5。
