## 1. 已定技术决策

| 决策项 | 结论 |
|---|---|
| 游戏框架 | **Godot 4.7.2**（gl_compatibility 渲染，兼容桌面/移动/Web 导出） |
| 脚本语言 | **GDScript**（2026-11-16 确认；蒙特卡洛性能瓶颈出现时再评估迁移） |
| 规则引擎形态 | 纯逻辑类（不依赖场景节点），单机练习与联机服务端共用一份代码 |
| 目录结构 | `core/`（规则引擎）/ `tests/`（轻量自研测试框架，headless 与进程内共用）/ `scenes/` + `scripts/`（UI） |
| 测试方案 | 自研轻量框架（`tests/run_tests.gd` headless 入口，失败退出码非 0，可接 CI）；主菜单「自检」按钮进程内复用同一套用例 |
| MVP 范围 | **单机练习优先**：完整一局流程 + AI 对手 + 每张候选出牌打分/胜率分析 |
| 联机对战 | 第二阶段：Godot 高层多人 API（ENet/WebSocket），服务端可用 Godot headless 跑房间逻辑 |
| 托管 | 免费平台（Web 导出可放静态托管；游戏服务器免费层到联机阶段再核实） |
| 目标端 | 桌面 + 移动（含 Web 导出） |
| 接入方式 | ZCode 官方 Godot 插件（godot:cli / godot:setup），编辑器安装于 `S:\Program\Godot\`（用户级环境变量 `GODOT_PATH` 已指向其主程序） |

### M2 实施记录（2026-11-16）

- `core/game.gd` 对局引擎（纯逻辑状态机，联机可复用）：拍卖（130 底叫/+5 倍数/封顶 200/放弃永久）、叫主（看底牌前）、翻底/扣底（底牌仅庄家可见）、逐轮出牌（复用 FollowRule 校验）、末轮抠底（单牌 ×1 / 对子·拖拉机 ×2）、分级（compute_outcome 纯函数）与收益（B=1，庄家净收/净付 3 份）、庄位轮换（规则 4）；种子化 RNG + 可注入牌型测试钩子
- `core/ai_policy.gd` 贪心策略（M2 基线，M3 可替换蒙特卡洛）：
  - 叫分：手牌强度评分（王/2/A/K/对子/潜在拖拉机加权）→ 档位映射
  - 叫主：花色按张数/大牌/对子加权；R 选持有量最大（成对 ×3 加成，平手取高点数）
  - 扣底：副牌分牌优先入底（8.2 策略注记），不扣常主
  - 领出：最大完整牌型（拖拉机 > 对子 > 单张）；跟牌：队友领先出最小（不拆台）、否则能赢用最小、赢不了出最小；杀：桌面 ≥10 分或最后一手才动用最小杀；垫：非主非分最低牌（防守方队友领先时垫分喂队友）
  - 观察记录：30 局自动对局中抠底 0 次——贪心庄家扣底常留主牌、末轮多由庄家赢下；8.2 路径由注入剧本确定性覆盖
- M1 模块小重构（行为不变）：`Trick.settle` 支持 1~4 份部分结算（"当前最大者"判定供 AI/UI 复用）；`FollowRule.list_tractors` 公开枚举
- UI（`scenes/game_table.tscn` + `scripts/game_table.gd` + `scripts/card_widget.gd` 程序化卡牌）：拍卖按钮组、叫主两步选择、扣底模式（底牌仅庄家可见）、点选出牌（非法出牌 toast 提示引擎原因）、轮次赢家标记、结算面板（明细+累计收益）、AI 行动 0.7s 节奏
- `tests/`：新增 14 项用例（结算档位、拍卖规则、叫主扣底流程、抠底 ×1/×2/庄赢不抠三剧本、庄位轮换、AI 单项与 30 局不变量、三局会话）+ `smoke_ui.gd`（headless 代打完整一局）
- 已知简化：人类固定 0 号位；B 固定 1；无复盘/历史（第 3 节待定事项）；AI 无打牌推理（M3）
